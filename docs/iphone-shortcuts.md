# iPhone ショートカットの作り方

iPhone の「ショートカット」アプリから、Life OS の Web API に次の2つを送ります。

| 送るもの | きっかけ | 送り先 |
|---|---|---|
| 睡眠（Apple Watch の睡眠データ） | 毎朝のオートメーション | `POST /api/ingest/sleep` |
| アプリを開いた・閉じた（Instagram / X / TikTok など） | アプリごとのオートメーション | `POST /api/ingest/app` |

- iPhone 側の利用制限は作りません（標準の「スクリーンタイム」で設定済みのものをそのまま使います）。
- 送った結果は、Web の **Today** の「睡眠」と「昨夜のDigital（iPhone）」に出ます。Mac とは分けて表示されます。
- 手順の画面名は iOS のバージョンで少し違うことがあります。迷ったら、各ステップの「何をするか」を目安にしてください。

---

## 0. 準備：iPhone 専用のトークンを作る

ショートカットには、Mac の拡張とは**別の、iPhone 専用のトークン**を使います。

- このトークンで呼べるのは、**睡眠とアプリ利用の送信（`/api/ingest/sleep`、`/api/ingest/app`）だけ**です。Today の閲覧や勉強の記録などには使えません。
- 漏れても、これだけ作り直せば済みます（Mac の拡張には影響しません）。
- Mac がなくても、iPhone だけで作れます。

### 0-1. トークンを作る（iPhone）
1. iPhone の **パスワード** アプリを開き、右上の **＋**（新しいパスワード）を押します。
2. **タイトル**に `LifeOS iPhone`、**ユーザ名**に `token` と入れます。**ウェブサイトの欄は空**のままにします（自動入力には使わないため。入れると「不完全なウェブサイトアドレス」の確認が出ます。出たら OK を押して構いません）。
3. **パスワード**の欄で、**強力なパスワードを使用** を選びます（`xxxxxx-xxxxxx-xxxxxx` のような20文字の文字列が入ります）。
4. 右上の **✓**（保存）を押します。

> パスワードアプリが使えないときは、英数字をでたらめに**20文字以上**、自分で入力して作っても構いません（例：`k7Qm-2xVd-9PzL-r4Ts-8Wn`）。短いと受け付けません。

### 0-2. Vercel に登録する（iPhone のブラウザ）
1. iPhone で Vercel（https://vercel.com）を開き、ログインします。画面が小さいときは、ブラウザの **ページのオプション（ぁあ）→ デスクトップ用 Web サイトを表示** にします。
2. `life-os-ufdi` のプロジェクト → **Settings** → **Environment Variables** → **Add Environment Variable** を開きます。
3. **Key**：`LIFEOS_IPHONE_TOKEN`、**Value**：0-1 のトークン（パスワードアプリで**コピー**して貼り付け）。
4. **Save** を押します。
5. **Deployments** を開き、**`Production` と付いた行**の **⋯ → Redeploy** を押して、**Ready** になるまで待ちます（Preview の行を再デプロイしても反映されません）。

### 0-3. つながるか確認する（任意）
ショートカットを作る前に、ブラウザでは確認できません（POST のため）。ステップ 2 のテスト用ショートカットが、そのまま確認になります。

### 認証ヘッダー
どのショートカットでも、リクエストは次の形です。

```
POST  {API の URL}/api/ingest/...
ヘッダー:
  Authorization: Bearer {iPhone 専用のトークン}
  Content-Type: application/json
本文: JSON
```

ヘッダーの値は、`Bearer `（最後に半角スペース）と入力してから、パスワードアプリのトークンを貼り付けます。

> トークンはショートカットの中に書くことになります。iCloud で他人と共有するショートカットには、入れないでください。

### 日付の書き方
日付は **ISO 8601**（例 `2026-10-07T00:20:00+09:00`）で送ります。
ショートカットの「日付をフォーマット」アクションで、形式を **ISO 8601** にします。
`2026-10-07 00:20:00` のようにタイムゾーンがない形でも受け付けます（日本時間として扱います）。

## 1. 睡眠を送るショートカット

名前：**LifeOS 睡眠を送る**

1. ショートカットアプリで **＋** を押し、新しいショートカットを作る。
2. アクション **ヘルスケアサンプルを検索** を追加する。
   - 種類：**睡眠**
   - 開始日：**過去 18 時間以内**
   - 並べ替え：**開始日**、**古い順**
   - 制限：オフ（すべて取得）
   - もし「覚醒（Awake）」のサンプルが混ざる場合は、条件に **値** を足して覚醒を除きます。
3. **リストから項目を取得** →「**最初の項目**」。
4. **ヘルスケアサンプルの詳細を取得** →「**開始日**」。
5. **日付をフォーマット** → 形式「**ISO 8601**」。
6. **変数を設定** → 名前 `就寝`。
7. もう一度、手順2で作ったリスト（**ヘルスケアサンプル**）を選び、**リストから項目を取得** →「**最後の項目**」。
8. **ヘルスケアサンプルの詳細を取得** →「**終了日**」。
9. **日付をフォーマット** → 形式「**ISO 8601**」。
10. **変数を設定** → 名前 `起床`。
11. **URL の内容を取得** を追加して、次のように設定する（「表示を増やす」を押す）。
    - URL：`{API の URL}/api/ingest/sleep`
    - 方法：**POST**
    - ヘッダー：
      - `Authorization` = `Bearer {トークン}`
      - `Content-Type` = `application/json`
    - 本文を要求：**JSON**
      - `sleep_at`（テキスト）= 変数 `就寝`
      - `wake_at`（テキスト）= 変数 `起床`
12. （任意）**通知を表示** →「睡眠を送りました」。

### 毎朝のオートメーション
1. ショートカットアプリの **オートメーション** → **＋** → **個人用オートメーション** → **時刻**。
2. 時刻：**7:30**（Apple Watch の睡眠データが iPhone に同期されたあと）、頻度：**毎日**。
3. アクション：**ショートカットを実行** →「LifeOS 睡眠を送る」。
4. **すぐに実行**を選び、**実行時に通知**はお好みで。

> 起床のタイミングで動かしたい場合は、トリガーに **睡眠 → 起床** を選ぶ方法もあります。
> 同じ夜のデータが何度届いても、Life OS 側で1件にまとめるので、二重に登録されません。

### 動作確認
- 手動で、ショートカットを1回実行する。
- Web の **Today** →「睡眠」に「昨夜の就寝 …（Watch）」と睡眠時間が出れば成功です。
- 「ボタンで記録した就寝」がある夜は、Apple Watch のデータが優先して表示されます（ボタンの記録は消えません）。

## 2. アプリの利用を送るショートカット

アプリごと・開く／閉じるごとに、ショートカットを1つずつ作ります（オートメーションは、どのアプリで動いたかを渡せないため）。
まず1つ作って、**複製**して名前と中身の文字だけ変えるのが楽です。

名前：**LifeOS Instagram 開く**

1. 新しいショートカットを作る。
2. アクション **現在の日付** を追加する。
3. **日付をフォーマット** → 形式「**ISO 8601**」。
4. **URL の内容を取得** を追加して設定する。
   - URL：`{API の URL}/api/ingest/app`
   - 方法：**POST**
   - ヘッダー：`Authorization` = `Bearer {トークン}`、`Content-Type` = `application/json`
   - 本文を要求：**JSON**
     - `app`（テキスト）= `Instagram`
     - `event`（テキスト）= `open`
     - `at`（テキスト）= 手順3の結果（フォーマットした日付）

複製して作るもの（`app` と `event` だけ変える）：

| ショートカット名 | `app` | `event` |
|---|---|---|
| LifeOS Instagram 開く | Instagram | `open` |
| LifeOS Instagram 閉じる | Instagram | `close` |
| LifeOS X 開く | X | `open` |
| LifeOS X 閉じる | X | `close` |
| LifeOS TikTok 開く | TikTok | `open` |
| LifeOS TikTok 閉じる | TikTok | `close` |

アプリ名は大文字・小文字を区別せずに集計されます（`TikTok` と `tiktok` は同じ）。

### アプリごとのオートメーション
アプリとイベントの組み合わせごとに、オートメーションを作ります（上の表と同じ6つ）。

1. **オートメーション** → **＋** → **個人用オートメーション** → **App**。
2. アプリを選ぶ（例：Instagram）。
3. **開いている** だけにチェックして次へ。（閉じる用は **閉じている** だけにチェック）
4. **ショートカットを実行** → 対応するショートカット（例：LifeOS Instagram 開く）。
5. **すぐに実行**にする。

### 動作確認
- Instagram を開く → 少しして閉じる。
- 数十秒後に Web の **Today** →「昨夜のDigital」の **iPhone** に出ます（**23:30 以降の利用だけ**が集計されます）。昼間に試したときは Today には出ませんが、API が成功していれば OK です。
- 開くだけで閉じる記録が届かなかったものは、利用時間として数えません。

## 3. 手動で API を確認する（curl）

ショートカットを作る前に、API が動いているか確認できます。

```sh
curl -X POST "https://xxxx.vercel.app/api/ingest/sleep" \
  -H "Authorization: Bearer $LIFEOS_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"sleep_at":"2026-10-07T00:20:00+09:00","wake_at":"2026-10-07T06:40:00+09:00"}'
# → {"night_date":"2026-10-06","updated":false}

curl -X POST "https://xxxx.vercel.app/api/ingest/app" \
  -H "Authorization: Bearer $LIFEOS_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"app":"Instagram","event":"open","at":"2026-10-07T00:10:00+09:00"}'
# → {"accepted":1}
```

同じコマンドをもう一度実行しても、記録は増えません。

アプリの記録はまとめても送れます。

```json
{ "events": [
  { "app": "Instagram", "event": "open",  "at": "2026-10-07T00:10:00+09:00" },
  { "app": "Instagram", "event": "close", "at": "2026-10-07T00:25:00+09:00" }
] }
```

## 4. うまくいかないとき

| 症状 | 確認すること |
|---|---|
| `認証が必要です`（401） | ヘッダーが `Authorization: Bearer ` + トークンになっているか。トークンが Vercel の `LIFEOS_API_TOKEN` と同じか |
| `sleep_at と wake_at が必要です`（400） | 本文が **JSON** になっているか。変数が空（睡眠データがない）になっていないか |
| `就寝と起床の時刻が正しくありません` | `就寝` と `起床` が逆になっていないか。16時間を超えていないか |
| `未来の時刻は記録できません` | 起床後（データが同期されたあと）に実行しているか。時刻を 7:30 以降にする |
| Today に出ない（睡眠） | 睡眠のデータが Apple Watch から iPhone に同期されているか（ヘルスケアアプリで確認） |
| Today に出ない（アプリ） | 開く・閉じるの両方が届いているか。利用が 23:30 より前ではないか |
